# 天地图 WMTS 适配服务

这是一个独立的 Python 服务，只依赖 Python 3.10 及以上版本的标准库，不需要安装第三方包。

它对天地图的 WMTS 服务描述进行适配，并原样转发官方瓦片。客户端访问本服务，由本服务向天地图附加服务 Key。**不修改瓦片图片，不做重投影、重采样、底图与注记合成，也不添加 GCJ-02 或 BD-09 偏移。**

支持矢量、影像、地形晕渲及其中文注记、境界叠加层，共 7 类、14 个官方服务入口，不是任意网址代理。

## 1. 本机启动

先安装 Python 3.10 或更新版本，在 PowerShell 中进入本文件所在目录，然后运行：

```powershell
.\start.ps1
```

启动器会提示输入天地图的**服务 Key**，输入内容不会显示，也不会保存到文件。服务启动后保持窗口运行，按 `Ctrl+C` 停止。

浏览器打开 <http://127.0.0.1:8765/> 可以查看服务入口。更换端口：

```powershell
.\start.ps1 -Port 8766
```

自动化部署时，也可以通过进程环境变量 `TIANDITU_TOKEN` 注入天地图 Key。不要把真实 Key 写进源码、文档、命令历史或版本库。

服务始终只监听 `127.0.0.1`。这些地址只能在服务所在机器访问，**本机启动不等于已完成公网部署**。启动时会先读取并校验全部 14 个上游服务的描述；如果 Key、网络或上游格网有问题，会拒绝启动。

## 2. 在客户端中使用

### 服务清单与推荐组合

以下层级为本次核实的官方声明范围及适配器输出范围，不代表每个区域、每个层级都有非空内容。所有瓦片均为 256 × 256 像素。

| 用途 | `w` 服务及矩阵范围 | `c` 服务及矩阵范围 | 客户端格式 |
| --- | --- | --- | --- |
| 矢量底图 | `vec_w`：1—18 | `vec_c`：1—18 | `image/png` |
| 矢量中文注记 | `cva_w`：1—18 | `cva_c`：1—19 | `image/png` |
| 影像底图 | `img_w`：1—18 | `img_c`：1—18 | `image/jpeg` |
| 影像中文注记 | `cia_w`：1—18 | `cia_c`：1—18 | `image/png` |
| 地形晕渲底图 | `ter_w`：1—14 | `ter_c`：1—14 | `image/jpeg` |
| 地形中文注记 | `cta_w`：1—18 | `cta_c`：1—18 | `image/png` |
| 境界叠加层 | `ibo_w`：1—18 | `ibo_c`：1—18 | `image/png` |

推荐只开启一组底图与对应注记，注记放在底图上方：

| 组合 | 底图 | 上方中文注记 | 可选境界 |
| --- | --- | --- | --- |
| 矢量 | `vec_w` | `cva_w` | `ibo_w` |
| 影像 | `img_w` | `cia_w` | `ibo_w` |
| 地形晕渲 | `ter_w` | `cta_w` | `ibo_w` |

所有入口遵循同一地址规则，将 `<服务标识>` 替换为表中的值：

```text
http://127.0.0.1:8765/<服务标识>/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0
```

图层标识是下划线前的部分，例如 `img`；矩阵集是后缀 `w` 或 `c`；样式均为 `default`。**影像、地形底图应选择 JPEG，不要沿用矢量底图的 PNG 设置。** 若客户端自动读取格式，使用服务声明的格式即可。

**地形晕渲是地图图片，不是 DEM 高程数据，也不是三维地形服务。** 添加 `ter` 不会让三维地表产生起伏。其底图最高第 14 级，继续放大时客户端可能放大已有图片或停止显示，不会获得更高层级的真实细节；不能把这个原有数据上限当成层级切换故障。

`ibo` 是叠加层，不是完整底图。在不包含境界线的局部区域，透明瓦片是正常现象。应按天地图展示要求核实必要的境界、署名和审图信息。

### 示例：矢量底图与中文注记

先添加矢量底图：

```text
http://127.0.0.1:8765/vec_w/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0
```

再添加中文注记：

```text
http://127.0.0.1:8765/cva_w/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0
```

| 配置项 | 矢量底图 | 中文注记 |
| --- | --- | --- |
| 服务路径 | `/vec_w/wmts` | `/cva_w/wmts` |
| 图层标识 | `vec` | `cva` |
| 瓦片矩阵集 | `w` | `w` |
| 样式 | `default` | `default` |
| 格式 | `image/png` | `image/png` |
| 显示顺序 | 在下方 | 在上方 |

`cva_w` 是透明的中文注记层，单独添加并不能代替完整底图。两层需要分别添加，本服务不生成合成图层。

### 通用 WMTS 客户端配置

1. 如客户端要求指定目标坐标系或瓦片格网，选择 **Web Mercator（EPSG:3857）**，与服务的 `_w` 后缀保持一致。
2. 在支持 WMTS 1.0.0 的客户端中新建 WMTS 连接，分别输入上面两个地址。
3. 按表格选择图层和矩阵集，将 `cva` 放在 `vec` 上方。客户端不需要再次填写天地图 Key。
4. 飞到北京等区域，等待加载完成；开关 `cva` 确认中文注记随之出现、消失，再连续放大、缩小，检查是否还有低清粗块或大字块。

影像组合使用 `img_w` 与 `cia_w`，地形晕渲组合使用 `ter_w` 与 `cta_w`，操作相同，但底图格式改选 JPEG。`ibo_w` 如需使用，作为透明叠加层添加。

更新服务后，如果已有图层保留了旧的服务描述或回退瓦片，移除并重新添加相关服务图层。服务地址保持不变。

## 3. 为什么需要适配器

WMTS 不只是一个“返回图片的网址”。客户端先读取 `GetCapabilities`，了解坐标系、范围、原点、瓦片大小、层级分辨率和请求方式，再据此选择瓦片行列。

本次遇到的问题主要在**服务描述与客户端解释之间的互操作性**，不是拿不到天地图图片：

| 遇到的问题 | 影响与适配方式 |
| --- | --- |
| 部分 `_w` 服务在 `WGS84BoundingBox` 中填写约 `±20037508` 的投影米坐标 | 该字段应使用经纬度的度值，严格客户端会报“坐标超出范围”。适配器按已确认的全球范围改写为经纬度边界。 |
| 部分比例尺分母的数值接近 96 DPI 约定，与按 WMTS 的 0.28 mm 参考像素解释所得的分辨率不一致 | 按已声明的全球矩阵尺寸反算分辨率，再输出一致的 `ScaleDenominator`，计算过程见第 5 节。 |
| `_w` 使用旧的 `900913` 标识，以及需要规范化的原点顺序、范围坐标系声明 | 使用等价的 `EPSG:3857` 标识，明确投影范围和左上角的坐标顺序；不转换瓦片坐标。 |
| `cva_w` 额外声明的第 19 级混入了地理格网的原点与行数 | 仅排除这个已确认异常的额外层级，保留有效的第 1—18 级，不臆造第 19 级数据。 |
| `cta_w` 声明 Web Mercator 坐标系和投影范围，但第 1—18 级全部填写地理格网的原点与行数 | 针对这一已确认的特定模式，恢复对应 `w` 格网的左上角与方形矩阵；仍请求原 `cta_w` 瓦片，不把 `cta_c` 图片伪装成投影图片。 |
| 访问天地图需要 Key | Key 由服务端保管并附加到上游请求，不出现在返回给客户端的服务描述中。 |

其中，向 `WGS84BoundingBox` 填入投影米坐标是明确的字段使用错误。但不能因此概括成“天地图全部不符合 OGC”，也不能把某个客户端对全球切片方案的要求当成所有 WMTS 服务都必须遵循的标准。

适配器只识别这里已验证的几种格网。如果上游出现未知坐标系、原点、矩阵尺寸或比例尺约定，会拒绝处理，而不是随意修改数值让客户端通过检查。

## 4. `w` 和 `c` 怎么选

| 对比项 | `c` 系列（如 `vec_c` / `cva_c`） | `w` 系列（如 `vec_w` / `cva_w`） |
| --- | --- | --- |
| 坐标参考系 | CGCS2000，`EPSG:4490` | Web Mercator，`EPSG:3857`；上游旧标识为 `900913` |
| 坐标单位 | 度 | 投影米 |
| 第一级矩阵 | 2 列 × 1 行 | 2 列 × 2 行 |
| 全球覆盖纬度 | -90° 至 90° | 约 -85.051129° 至 85.051129° |
| 客户端要求 | 需要明确支持该坐标系的缓存瓦片格网 | 需要支持 Web Mercator 缓存瓦片格网 |

**通常优先选择客户端明确支持的格网。** Web Mercator 缓存瓦片客户端可以使用 `w`；需要 CGCS2000 地理格网且具备相应绘制能力的客户端可以使用 `c`。这不是坐标系是否合法或精度高低的判断。

WMTS 提供的是按固定格网预先切好的图片。客户端支持几何坐标动态投影，并不必然表示它也能在任意二维或三维视图中重投影缓存瓦片。需要核实客户端对服务坐标系、格网和目标视图的支持，不能仅凭服务描述加载成功判定一定能绘制。

本服务保留所有 7 类服务的 `c` 入口，例如：

```text
http://127.0.0.1:8765/vec_c/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0
http://127.0.0.1:8765/cva_c/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0
```

它们保留真正的 `EPSG:4490` 和矩阵集 `c`，不会把坐标系改名成 `EPSG:4326` 来绕过检查。`c/w` 的区别也不是 GCJ-02 或 BD-09 偏移开关；本服务不添加这些偏移。

## 5. 第一级分辨率是怎么算的

### 5.1 分辨率就是“一个像素覆盖多少地图坐标单位”

最直接的计算方法：

```text
分辨率 = 地图覆盖宽度 ÷（水平方向瓦片数量 × 每张瓦片的像素宽度）
```

这里的“第一级”指天地图声明的 **TileMatrix 标识 `1`**。某些客户端会从 `0` 开始编号内部 LOD，不能因此把向天地图请求的矩阵标识 `1` 改成 `0`。

### 5.2 `c`：为什么是 0.703125 度/像素

地理格网的全球经度跨度是 360°，第一级有 2 列瓦片，每张宽 256 像素：

```text
水平像素总数 = 2 × 256 = 512
首级分辨率 = 360° ÷ 512 = 0.703125°/像素
```

纵向也能验证：纬度跨度为 180°，只有 1 行瓦片，因此：

```text
180° ÷（1 × 256）= 0.703125°/像素
```

注意单位是**度/像素，不是米/像素**。经度 1° 对应的实际地面距离会随纬度变化，不能把这个度值直接当作米值。

### 5.3 `w`：为什么是 78271.516964 米/像素

Web Mercator 使用的球面半径为 `R = 6378137` 米。投影横坐标从 `-πR` 到 `+πR`，全球投影宽度为：

```text
全球投影宽度 = 2 × π × 6378137
             ≈ 40075016.68557849 米
```

第一级同样有 2 列、每张 256 像素：

```text
首级分辨率 = 40075016.68557849 ÷（2 × 256）
           ≈ 78271.5169640205 投影米/像素
```

常见 XYZ 格网的 `zoom 0` 只有 1 列，因此其分辨率约为 `156543.033928041` 米/像素。天地图这里从矩阵 `1`、2 列开始，分辨率自然是前者的一半，并不矛盾。

这里的“米”是**投影平面上的米**，不是所有纬度都相同的真实地面距离。在球面近似下，纬度 `φ` 处的地面分辨率约为 `投影分辨率 × cos(φ)`。

### 5.4 后续层级怎么计算

这些格网每加一级，横向、纵向瓦片数量都翻倍，所以每像素覆盖的坐标范围减半：

```text
第 L 级分辨率 = 首级分辨率 ÷ 2^(L - 1)，其中 L 从 1 开始

c：0.703125、0.3515625、0.17578125…… 度/像素
w：78271.516964、39135.758482、19567.879241…… 投影米/像素
```

### 5.5 分辨率与 `ScaleDenominator` 是什么关系

`ScaleDenominator` 是比例尺分母，例如数值 `10000` 表示参考比例尺 `1:10000`。它不是分辨率本身，换算时需要约定一个像素在显示介质上的物理尺寸。

WMTS 使用 **0.28 mm，也就是 0.00028 米**的参考像素。这是标准换算约定，不是要求实际显示器的像素必须有这么大。

```text
比例尺分母 = 分辨率 × 每坐标单位对应的米数 ÷ 0.00028
```

对于 `w`，单位已经是投影米，所以：

```text
首级比例尺分母 = 78271.5169640205 ÷ 0.00028
               ≈ 279541132.0143589
```

对于这里的地理格网，采用赤道方向的换算约定：

```text
每度对应的米数 = π × 6378137 ÷ 180
               ≈ 111319.49079327358 米/度

首级比例尺分母 = 0.703125 × 111319.49079327358 ÷ 0.00028
               ≈ 279541132.0143589
```

两种格网的首级比例尺分母恰好相同，**不代表它们是同一种格网**：坐标系、单位、纵向行数、覆盖纬度都不同。

### 5.6 为什么原来会读到约 0.74409449，而不是 0.703125

96 DPI 约定下，一个显示像素的物理尺寸为：

```text
0.0254 米/英寸 ÷ 96 像素/英寸
≈ 0.0002645833333333333 米/像素
```

本次上游的部分数值接近按这个尺寸换算的结果：

```text
78271.5169640205 ÷（0.0254 ÷ 96）
≈ 295829355.4545656
```

如果客户端把这个数值当成基于 WMTS 0.28 mm 参考像素的比例尺分母，会反算出：

```text
295829355.4545656 × 0.00028 ÷ 111319.49079327358
≈ 0.7440944882 度/像素
```

它比矩阵尺寸要求的 `0.703125` 大约多 5.83%，所以“按范围和瓦片数量算出的格网”与“按比例尺分母读出的格网”不一致。

**适配器改的是服务描述中的换算结果，不是图片，也不是把地理坐标挪到别处。** 客户端还可能把 WMTS 比例尺换算成自身的显示比例尺，因此不能只比较界面或 API 最后显示的比例尺数字；应同时核对服务描述、矩阵尺寸和实际分辨率。

## 6. 其他适配行为与边界

- `c` 保留 4490。其左上角按声明的坐标轴顺序为“纬度 90、经度 -180”，第 L 级为 `2^L` 列、`2^(L-1)` 行。
- `w` 使用 3857。左上角按东向、北向坐标为 `(-20037508.342789244, +20037508.342789244)`，第 L 级为 `2^L` 列和行。
- 客户端访问适配器地址；适配器只请求固定的天地图官方 HTTPS 地址，校验 TLS，并拒绝上游重定向，防止 Key 被带到其他站点。
- 影像与地形晕渲底图对外格式为 `image/jpeg`，其他图层为 `image/png`；向上游请求时使用其原有的 `FORMAT=tiles`。按图片签名和头部校验 256 × 256 尺寸，不依赖上游非标准的 `image/jpg` 名称，也不重新编码图片。
- 瓦片矩阵标识和图片字节保持不变；仅省略前文说明的异常 `cva_w` 第 19 级。
- 服务描述在内存缓存 5 分钟。服务本身不把瓦片或 Key 写入磁盘；客户端、终端或反向代理可能有自己的缓存和日志，应另行配置。
- 使用 HTTP/1.1 持久连接，并明确响应字节长度，支持在同一连接上连续请求服务描述和瓦片。

## 7. 公网部署

不要把 Python 标准库的 HTTP 监听器直接暴露到互联网。应保持其监听本机，由 **HTTPS 反向代理**对外服务，并配置独立的客户端访问令牌：

```powershell
$env:PUBLIC_BASE_URL = 'https://wmts.example.com'
$env:WMTS_ACCESS_TOKEN = python -c "import secrets; print(secrets.token_urlsafe(32))"
.\start.ps1
```

其中：

- `PUBLIC_BASE_URL` 是你自己的 HTTPS 域名地址，不能包含额外路径、查询参数或用户名密码。
- `TIANDITU_TOKEN` 是访问天地图的服务 Key，只供服务端使用。
- `WMTS_ACCESS_TOKEN` 是你生成并安全分发给授权使用者的客户端令牌，至少 24 个 ASCII 字符，**不是天地图 Key**。

先准备域名、DNS 和可信 TLS 证书。例如单独安装 Caddy 后，可以使用以下反向代理配置：

```caddyfile
wmts.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

将域名换成自己的域名后，授权客户端使用以下地址，并把 `<客户端令牌>` 替换成实际生成的值：

```text
https://wmts.example.com/vec_w/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0&access_token=<客户端令牌>
https://wmts.example.com/cva_w/wmts?SERVICE=WMTS&REQUEST=GetCapabilities&VERSION=1.0.0&access_token=<客户端令牌>
```

这是配置范例，不表示服务已经公网部署。公网模式会在返回的操作地址中保留客户端令牌，并允许通过令牌认证的浏览器跨域访问。**含客户端令牌的链接、项目文件和导出的服务描述也应按敏感信息管理。** 天地图 Key 不会出现在这些地址中。

反向代理应限制访问范围、请求频率和并发数，不记录完整查询字符串；更换令牌或环境配置后重启服务。本服务日志同样不记录查询字符串。匿名的 `/healthz` 仅检查监听器是否就绪，不保证天地图上游始终可用。

## 8. 使用与合规提醒

这是一项协议互操作适配，不是 OGC 合规认证、坐标精度鉴定或地图合规证明。需要用可信的控制点验证实际位置精度，不能仅凭“能显示”判定没有偏移。

使用或公开部署前，应核实天地图 Key 的适用范围、代理与再分发权限、调用配额、来源署名、著作权和审图号等要求，按规定展示必要标识。本服务不替代这些授权，也不补造审图信息。
